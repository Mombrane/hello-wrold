# 极限稀疏 MoE 的训练稳定性：Quantile Balancing 与 SiTU-GLU

> **核心发现：Quantile Balancing 通过分位数反推实现零辅助损失的专家均衡，SiTU-GLU 用软截断替代无界激活，共同支撑896选16的极限稀疏路由。**
> 调研日期：2026-07-29 | 来源：K3 技术报告、DeepSeek-V3 Aux-Loss-Free (arXiv:2408.15664)、GShard (2020)、OpenAthena QB 验证报告 (2026)

---

## 一、概览

**K3 将 MoE 稀疏度推到极端——896个专家中每token仅激活16个（利用率1.8%），路由崩塌和激活爆炸成为一阶挑战。Quantile Balancing 和 SiTU-GLU 分别解决这两个问题。**

MoE 架构的核心折中：总参数量大，但每次计算只激活少量专家。Kimi K2 配置为384专家激活8个（利用率2.1%），K3 进一步压缩到896→16。稀疏度从 K2 的48倍提升到56倍（K3 技术报告，2026）。

在这个量级下，两个原本可控的问题变得致命：

1. **路由崩塌**：少数专家被反复选中，其余闲置——传统辅助损失（Auxiliary Loss）在896专家时梯度干扰远超收益（GShard, 2020）
2. **激活爆炸**：路由路径连续4次矩阵乘法，无界激活函数（如 SwiGLU）的中间值可能溢出，在低精度训练（MXFP4）下尤为危险

K3 的对策：Quantile Balancing 管负载均衡，SiTU-GLU 管数值稳定。两项技术共同支撑了 K3 在2.8万亿参数规模上的稳定训练，整体扩展效率相比 K2 提升约2.5倍（K3 技术报告）。

> **My take**：这是 MoE 从"百级专家"跃升到"千级专家"的关键工程突破。没有这两项技术，896→16 的训练极大概率为不可行或代价极高。但它们解决的是训练稳定性，不是专家的能力质量——896个专家是否都学到了有价值的表征，是另一个问题。

## 二、Quantile Balancing：分位数反推的精确均衡

**QB 不从损失函数中加惩罚项，而是直接计算"录取线"——对每个专家，根据上一批次的路由分数分位数，反推出使负载均衡的偏置值。一步到位，无需超参数调优。**

### 2.1 传统方法的困境

辅助损失（Auxiliary Loss）是 GShard (Lepikhin et al., 2020) 引入的标准做法：

```
L_total = L_LM + α · N · Σ(f_i · P_i)
```

其中 f_i 是专家 i 处理的 token 比例，P_i 是平均路由分数。问题在于：

- **梯度干扰**：平衡损失的梯度与语言建模梯度方向不一致，路由器被两个目标拉扯（DeepSeek-V3 技术报告，arXiv:2408.15664）
- **α 超参脆弱**：太小（< 0.001）则均衡失效，太大（> 0.01）则模型性能下降；且最优值随模型规模、训练阶段变化

DeepSeek-V3 (Wang et al., 2024) 提出 Aux-Loss-Free 偏置法：

```
b_i ← b_i - γ · sign(N_i - N_target)
```

其中 N_i 是专家 i 的实际负载，N_target 是目标负载，γ 为固定步长（通常 1e-3 ~ 1e-4）。优势在于不引入辅助损失到优化目标中，但问题在于：

- **步长依然是超参数**：太小则调整慢，太大则震荡——896个专家场景下尤为突出（K3 技术报告引用）
- **依赖迭代收敛**：偏置从零开始，需要多步才能逼近目标值

### 2.2 QB 的核心机制

K3 的 Quantile Balancing 完全跳出"调步长"的框架，直接一步求解：

```
b_j = -Quantile_{1 - k/n} (s_{:,j})
```

其中：
- s_{:,j} 是所有 token 对专家 j 的路由分数分布
- k/n = 16/896 = 1.8%，即目标激活比例
- 偏置 b_j 即为路由器分数的第 (1 - 1.8%) 分位数取负值

**直觉**：如果希望每个专家被 1.8% 的 token 选中，那只需计算"前1.8%的token打到该专家的最低分数"，取其相反数作为偏置。加上偏置后，恰好1.8%的token分数为正，其余为负——完美均衡。

**直方图估计**：在数百万 token 上精确计算分位数，K3 采用分桶计数法（直方图近似）。将 [0,1] 区间等分为 b 个桶，对每个专家的路由器分数做 one-hot 分桶，沿序列维度做指数移动平均（EMA），得到分布后再求分位数。EMA 保证了计算可并行且保持因果性（使用上一批次数据）。

### 2.3 三种方法的公式级对比

| 维度 | Auxiliary Loss (GShard) | DeepSeek-V3 Bias | Quantile Balancing (K3) |
|------|------------------------|-------------------|------------------------|
| 机制 | L_aux = α·N·Σ(f_i·P_i) | b_i ← b_i - γ·sign(N_i - N_target) | b_j = -Quantile_{1-k/n}(s_{:,j}) |
| 收敛速度 | 中等（依赖α调优） | 较快（依赖γ调优） | 瞬时（一步到位） |
| 超参数敏感性 | **高**（α=0.001~0.01） | **中**（γ=1e-3~1e-4） | **低**（无需调优） |
| 梯度干扰 | 有（损失项直接污染梯度） | 无（偏置不参与梯度计算） | 无（偏置不参与梯度计算） |
| 因果性保证 | 序列级（α作用于当前batch） | 批次级（偏置用上一步信息） | 批次级（直方图用上一步分布） |
| 896专家适用性 | 差（α几乎不可调） | 一般（γ需要针对规模重调） | **好**（分位数天然尺度不变） |

**QB 为什么不需要步长超参数**：分位数直接从分布中反推目标值，不依赖迭代。DeepSeek 方法需要 b_i 从 0 逐步调整到目标值——这本质上是一个 PID 控制问题，γ 是增益系数。而 QB 等价于直接求解稳态解，跳过瞬态过程。

### 2.4 工程实现细节

- QB 在每一层的每个 MoE 块独立运行
- 直方图桶数 b 是唯一的工程参数（K3 未公开具体值，Marin 的实现使用数十到数百桶）
- 偏置项使用上一步（而非当前步）的分数计算，保证训练因果性
- 与 MoonEP（K3 的专家并行训练框架）协同：QB 负责算法层路由均衡，MoonEP 负责硬件层执行均衡

**OpenAthena/Marin 的独立验证** (Dial, 2026)：在 32B-A5B（64专家，激活4个）规模下，QB 实现了零 loss spike 的稳定训练，且不需要前导密集层或辅助损失辅助。相比之下，传统 fixed-increment bias + aux-loss 方案在训练早期（前5000步）出现专家负载剧烈波动，部分专家死锁 50+ 步后才恢复。

> **My take**：QB 的优雅在于它把"均衡"从优化问题降级为统计算术——不需要学习、不需要调参、不需要退火。但它的一个隐含假设是"每个专家应该被等量使用"——这个假设是否在所有层、所有训练阶段都成立？OpenAthena 已经观察到某些层的专家天然在 70% 负载下运行，这暗示均衡本身不一定是唯一合理的目标。

## 三、SiTU-GLU：软截断的激活稳定性

**SiTU-GLU 在门控分支和值分支分别用 tanh 做软截断，将激活值限制在 [-100, 100] 范围内。小值时行为接近 SwiGLU，大值时饱和有界——在 MoE 专家网络的深层计算中防止激活爆炸。**

### 3.1 公式与界

```
SiTU-GLU(x) = β₁ · tanh(W_g x / β₁) ⊙ σ(W_g x) ⊙ β₂ · tanh(W_u x / β₂)
```

- **β₁ = 4**：控制门控分支饱和点，tanh 在 |z| > 4 时输出接近 ±1
- **β₂ = 25**：控制值分支饱和点，tanh 在 |z| > 25 时输出接近 ±1
- **输出界**：|f(x)| ≤ β₁ · β₂ = 100

### 3.2 行为分析

在原点附近，β · tanh(z/β) ≈ z（一阶泰勒展开），因此：

```
SiTU-GLU(x) ≈ (W_g x) ⊙ σ(W_g x) ⊙ (W_u x)   （|x| 较小时）
```

这恰好是 SwiGLU 的形式（SwiGLU 定义为 W_g x ⊙ σ(W_g x) ⊙ W_u x）。当输入变大时，tanh 开始饱和，激活值被压回有界区间。K3 报告将此描述为"小值响应、大值截断"。

### 3.3 与其他激活函数的对比

| 激活函数 | 输出有界？ | MoE 专家稳定性 | 推理速度 | 训练速度 |
|---------|----------|--------------|---------|---------|
| SwiGLU | 无界 | 差（激活尖峰频发） | 最快 | 最快 |
| GeGLU | 无界 | 差 | 中等 | 中等 |
| ReGLU | 半有界（下界=0） | 中等 | 中等 | 中等 |
| **SiTU-GLU** | **有界（100）** | **最好** | 慢（无融合算子时约3倍） | 慢（无融合算子时约3倍） |

来源：SwiGLU (Shazeer, 2020)，GeGLU/ReGLU，SiTU-GLU (K3 技术报告, 2026)

### 3.4 为什么 MoE 专家网络中需要有界激活

路由路径的矩阵乘法链：
```
token → RMSNorm → Router(gate) → Expert_MLP → RMSNorm → Expert_MLP → RMSNorm → ...
```

每经过一个无界激活函数（如 SwiGLU），分布的上尾可能被拉长。在896专家、每层16激活的设置下，同一 token 会连续经过多个专家层（K3 有93层，每层含 MoE 块）。四次矩阵乘法的累积效应下，即使单步激活放大因子仅为 2-3 倍，全链路的放大可达 16-81 倍。

K3 的双层保护策略：
1. **RMSNorm**：每层 MoE 块前后均做归一化，控制输入的分布尺度
2. **SiTU-GLU**：专家内部做软截断，控制输出的最大幅值

两层保护互补：RMSNorm 管输入，SiTU-GLU 管输出。

### 3.5 代价与缓解

SiTU-GLU 的主要代价是**速度**。标准 SwiGLU 可以融合为单一 CUDA kernel（sigmoid + multiply），而 SiTU-GLU 涉及两次 tanh、一次 sigmoid、三次乘法——没有融合算子时，实测比 SwiGLU 慢约 3 倍。

K3 的缓解方案：让专家在**压缩的潜在空间**（latent space）中运行。Stable LatentMoE 将专家计算的维度压缩后再接回去，降低每次 SiTU-GLU 调用的实际计算量。报告未给出精确的端到端开销百分比，但声称这是可接受的代价。

> **My take**：SiTU-GLU 本质上是一个工程补丁——在 MoE 训练足够稳定时，没人会愿意为 3x 慢的激活函数买单。但在 896→16 的极端设置下，它是"没有更好的选择"的选择。让人好奇的是，β = (4, 25) 这个设置是否经过了系统性搜索？还是手工调节的结果——K3 报告没有给出消融实验。

## 四、实际效果与工程考量

**QB 和 SiTU-GLU 在 K3 的2.8万亿参数训练中交付了2.5倍的扩展效率提升（vs K2），报告声称训练全程稳定无崩溃。但两者都缺乏精确的消融数字——效果更多是定性的"使训练成为可能"而非定量的"比基线提升X%"。**

### 4.1 QB 与 DeepSeek-V3 偏置法的收敛对比

DeepSeek-V3 偏置法（b_i ← b_i - γ·sign(·)）在 256 个专家时表现优异。但当扩展到 896 专家时：

- 固定步长 γ 需要针对规模重新搜索（K3 未给出搜索范围）
- 偏置从 0 到稳态需要多步迭代，训练初期路由不稳定
- OpenAthena 验证：fixed-increment bias 在 64 专家时前 5000 步仍有混乱，896 专家只会更差

QB 的"一步到位"特性在 896 专家时优势最大——分位数天然与专家数量解耦，896 和 64 的计算逻辑完全一致。

### 4.2 SiTU 的激活爆炸抑制

K3 报告未给出精确的激活尖峰统计（如"SwiGLU 下第 N 层出现 >1000 的激活尖峰频率"），仅定性陈述"SiTU-GLU 有效控制了低精度训练中的溢出风险"。

已知的间接证据：
- K3 使用 MXFP4 权重 + MXFP8 激活进行量化感知训练（QAT）
- MXFP8 的动态范围远小于 FP16/BF16，对激活溢出更敏感
- 训练全程无 loss spike（K3 技术报告），间接证明激活控制有效

**关键的混淆因素**：K3 仅发布 MXFP4 量化检查点，无法独立验证 SiTU 在 FP16/BF16 下的效果。SiTU 对训练稳定性的贡献可能与量化格式耦合——FP16 下 SwiGLU 可能已经没有溢出问题，但 MXFP4 下有。

### 4.3 β 参数的选择

K3 报告给出的 β = (4, 25) 是最终使用的值，但：
- 未说明选择方法（手工？网格搜索？贝叶斯优化？）
- 未报告消融实验（如 β=(2,12)、(8,50) 的效果对比）
- 原理解释是启发式的："β₁=4 确保门控在合理范围内饱和，β₂=25 提供足够的线性区间"

这留下了 β 选择是一阶"够好就行"还是经过精心调优的疑问。

### 4.4 训练各阶段的 bias 收敛行为

基于 OpenAthena 的 QB 可视化（64专家），训练全周期的偏置演变大致为：

1. **初始阶段（步 0-1000）**：路由器分数接近均匀，分位数估计噪声大，偏置波动明显
2. **收敛阶段（步 1000-20000）**：分布稳定后，偏置快速收敛到稳态值
3. **稳态阶段（步 20000+）**：偏置在小范围内微调，跟踪数据分布漂移
4. **Cooldown 阶段**：如果使用学习率退火或数据分布切换，偏置需要重新适应

896 专家的场景可能还需要考虑"死专家复活"——如果某个专家因随机初始化劣势长期得不到 token，偏置能否将其"拉回来"？OpenAthena 的 64 专家实验显示这对专家在 70% 负载停滞，但未出现 0% 的情况。

> **My take**：K3 报告对实际效果呈"成功叙事"风格——强调工作的、不提失败的。这是工业报告的常态，但��为技术调研，我们必须标注出哪些结论有数据支撑、哪些是推断。

## 五、批判性分析与开放问题

**QB 和 SiTU-GLU 是切实的工程突破，但多项关键细节未公开——包括训练早期的鲁棒性、β 参数的消融、极端稀疏下的专家利用率分布。以下问题将决定这两项技术能否成为 MoE 基础设施的"标准件"。**

### 5.1 QB 训练早期的鲁棒性

直方图估计在训练早期面临双重困难：
- 样本量少（每个专家的 token 计数低）
- 路由器分数分布高度不稳定（随机初始化 + 路由器快速学习）

**推测**：K3 可能在训练初期使用 warmup 机制——例如前几千步使用 DeepSeek 偏置法过渡，或增大直方图的 EMA 衰减系数以提高稳定性。但 K3 报告未明确说明。第三方报道（腾讯新闻）也提出了同样的担忧："训练早期这种估计会比较嘈杂，可能需要额外的预热机制"。

### 5.2 896→16 下专家的实际利用率

QB 保证每个专家处理的 token 数量接近均衡，但这不等于专家质量均衡：

- 均衡只在**负载**（token count）层面成立，不在**路由分数**（router score）层面
- 可能存在"凑数专家"——偏置被大幅拉升以接受更多 token，但实际路由分数很低
- K3 未公布每个专家的路由分数分布（仅公开了负载统计）

OpenAthena 的观察："QB 不直接推开路由向量，只加一个次级偏置项"——这意味着专家的表征特殊性依赖路由器自身的学习，QB 不干预专家的专业化过程。

### 5.3 SiTU-GLU 的 β 消融缺失

(4, 25) 是一个看似合理的组合，但没有消融支撑。理论上有意义的对比：

| β 组合 | 输出界 | 预期行为 |
|--------|-------|---------|
| (2, 50) | 100 | 门控更早饱和，值分支更线性 |
| (4, 25) | 100 | K3 默认 |
| (8, 12.5) | 100 | 门控更线性，值分支更早饱和 |
| (1, 100) | 100 | 极端门控饱和，值分支几乎无界 |

不同组合对应不同的"截断位置"——是门控先饱和还是值分支先饱和？这可能影响专家的激活模式。**当前的状态更像是"能 work"而非"找到最优"**。

### 5.4 MXFP4 检查点的不可分离性

K3 仅发布 MXFP4 量化权重。无法进行以下关键对照实验：
- SwiGLU + MXFP4 → 训练是否稳定？（排除 SiTU 贡献）
- SiTU-GLU + BF16 → 溢出是否仍然发生？（排除量化耦合）
- 结论：SiTU 的有效性是**关联证据**而非**因果证据**

### 5.5 对开源社区的启示

尽管存在上述开放问题，QB 和 SiTU-GLU 的可复用性很高：

| 技术 | 可替换性 | 适用场景 |
|------|---------|---------|
| Quantile Balancing | **直接替代 DeepSeek-V3 偏置法** | 任何 top-K MoE 路由 |
| SiTU-GLU | **可直接复用**，但需评估速度代价 | 低精度训练或深层 MoE |
| 双层保护（RMSNorm + SiTU） | 最佳实践参考 | 极限稀疏 MoE |

Marin (OpenAthena) 已在独立代码库中验证 QB 的有效性，JAX 实现已开源（Marin GitHub，2026）。SiTU-GLU 尚未见第三方独立验证。

### 5.6 未回答的核心问题

1. **896 个专家是否都形成了有意义的专业化？** 均衡 ≠ 质量。
2. **β 值是否有更优解？** 缺消融。
3. **QB 在训练超早期（步 0-100）的行为？** 未描述。
4. **SiTU 在 BF16/FP16 下是否仍然必要？** 无法验证（仅 MXFP4 可用）。
5. **两项技术的交互效应？** QB 管均衡、SiTU 管稳定——但它们是否独立？均衡的专家是否意味着更少的激活尖峰？

> **My take**：QB 已经展现出足够强的实用性，大概率成为未来 MoE 训练的默认负载均衡方案——它的"零超参数"特性太有吸引力。SiTU-GLU 的前景取决于两点：一是能否开发出融合 CUDA kernel 把速度拉到接近 SwiGLU；二是有没有更好的有界替代方案（如 clamped SiLU、有界 GELU 变体）。
